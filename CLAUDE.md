Static marketing site for **NexOne World** (company), product **NexOne** (an ERP). Six pages: home, about, contact, why-us, inventory, logistics.

## Rules

1. **Match the old design.** When unsure, open the legacy file and copy it. See *Sources that no longer exist* below — for some sections there is nothing left to open.
2. **Don't convert existing CSS to Tailwind utilities.** Paste it verbatim into `src/styles/sections/*.css`. `padding: 26px` silently becomes `p-6` (24px); a hundred of those break the design. Utilities are for new markup only.
3. **Never hardcode hex in CSS.** All colours come from `@theme` in `global.css`. *Exception:* SVG **presentation attributes** (`stroke="…"`, `stop-color="…"`) do not accept `var()` — the hero chart at `index.html:2482` is the live case. Move the colour into a CSS rule, or use `currentColor`. Don't leave a raw hex sitting in the attribute.
4. **Orange type on light backgrounds uses `--color-orange-text`** (`#B05A00`). `#FA7B0D` on `#FAFAFA` is 2.55:1 and fails AA; `#B05A00` is 4.67:1 and passes. Fills, icons and borders keep `#FA7B0D`.
5. **One orange element per viewport.** Grep the section for `--color-orange` before adding another.
6. **Every CTA needs a real `href`.** The old build has 32 anchors pointing at `href="#"` — index 16, contact 4, about/inventory/logistics/why-us 3 each. Grep `href="#"` when you finish a page; it should return nothing.
7. **Never invent** testimonials, statistics, certifications or team members. Content that already exists in `legacy/` and has been confirmed approved ports across as-is — see *Approved content* below. Anything you cannot trace to a legacy file or an explicit approval gets a placeholder slot and a note saying so.
8. **No revenue figures, currency amounts or headcount in prose copy.** This governs sentences you write. It does **not** govern the decorative hero dashboard mock, which keeps its real strings (`USD 1.24M`, `USD 340K`) — that is design, and rule 1 wins there.
9. **320px to 1920px.** Most traffic is a WhatsApp link opened on a phone.
10. **Grep before editing.** Verify the current file state rather than trusting a description of it — including this file, and especially `legacy/CLAUDE.md`.
11. **`.container` is always the legacy 1280px container** (`base/layout.css`, `max-width: 1280px`, aliased to `--container-site` in `theme.css`) — not the scaffold placeholder's 1440px/120px gutter.

**A new effect almost certainly does not belong in GSAP.** Since the 2026-08-27 performance pass the default is CSS + a small IntersectionObserver; see *Animation architecture* below for which file to put it in.

Legacy uses `.reveal-group > .reveal` with a single `IntersectionObserver` and per-index stagger delays to `:nth-child(10)`. You are replacing that with `data-anim`. Two traps from the legacy log apply while both systems coexist: `.reveal` silently owns the hover transition of any card it sits on, and `.reveal-group > .reveal` clobbers a custom-styled child unless specificity matches. Strip `.reveal` classes as you convert a section rather than leaving them alongside.

Two known defects in the current engine, worth fixing when you first hit them:
- **The pre-animation state flashes.** `global.css` hides `[data-anim]` only once `.js-ready` is on `<html>`, but `initAnimations()` sets that class from a deferred module script in `<body>` — so content paints visible, then hides, then animates. Set `js-ready` from a tiny inline `<head>` script instead.
- **`marquee()` seams and ignores hover gating.** It clones its children exactly once and computes `scrollWidth / 2`, so 8 logos narrower than a wide viewport leave a visible gap; and it binds `mouseenter`/`mouseleave` with no `(hover: hover)` guard.

## Animation architecture

Rebuilt 2026-08-27 for performance. **The markup contract below did not change** — `data-anim` and its modifiers work exactly as they always did. What changed is what runs them, and the rule is now: *GSAP is the exception, not the engine.*

| what | where | dependency |
|---|---|---|
| scroll reveals (`fade-up`, `fade-in`, `scale-in`, `stagger`, `draw`, `clip`) | `lib/reveal.ts` + `base/animation.css` | none |
| hero entrance | `sections/hero.css` | none |
| trust marquee | `lib/marquee.ts` | none |
| flow scrub, parallax, architecture pulses | `lib/scroll-fx.ts` + `sections/architecture.css` | none |
| mobile nav open/close | `base/responsive.css` | none |
| click reveals inside islands | `lib/motion.ts` + `base/animation.css` | none |
| **hero H1 scramble, comparison scatter/scramble** | `lib/animations.ts` | **GSAP, lazy** |
| platform grid restructure | `sections/platform.css` (`transition` on `.platform-shell`/`.platform-grid`/`.platform-icon`) | none |

`lib/boot.ts` owns load order and the decision of whether to fetch GSAP at all. It does not, on: reduced motion; a "lite" device (`lib/motion.ts` — Save-Data, a 2G-class connection, or weak CPU *and* low memory together); or any page with neither a hero H1 nor a comparison canvas. So `/about`, `/contact`, `/why-us` and all six module pages never load GSAP, and neither does a phone on a bad connection anywhere on the site.

**Consequences worth knowing before you edit any of it:**

- **No blanket `will-change`.** It used to sit on every `[data-anim]` element and was the main source of scroll jank on phones — see the mistake log. Don't put it back.
- **Reveals use `translate`/`scale` as individual properties**, never `transform`, so they compose with a section's own authored `transform` instead of wiping it.
- **`display: contents` and `display: none` wrappers can't be observed.** `reveal.ts` walks up to the nearest ancestor with a box; `.pain-grid` is the live case. A `display: none` panel needs `revealNow()` instead (industry tabs).
- **Whatever you add to `lib/animations.ts` will not run for lite devices or reduced motion.** If an effect has to run everywhere, it cannot live there.

## Animation reference

```html
<section data-anim="fade-up">
<div data-anim="fade-in">                             <!-- opacity only -->
<div data-anim="stagger" data-anim-stagger="0.08">    <!-- children in sequence -->
<div data-anim="scale-in" data-anim-delay="0.2">
<div data-anim="clip">                                <!-- wipe from bottom -->
<div data-anim="pin" data-pin-length="1.5">           <!-- sticks while page scrolls -->
<path data-anim="draw" />                             <!-- SVG line draws -->
<span data-anim="count" data-count-to="40" data-count-suffix=" min">
<img data-anim="parallax" data-speed="0.12">
```

Modifiers: `data-anim-delay`, `data-anim-duration`, `data-anim-start`, `data-anim-stagger`.

Per section (all 11): **Hero** `split-lines` on `.hero-title`/`.hero-lede`, `fade-up` (staggered via `data-anim-delay`) on eyebrow/actions/proof/image — see *Motion, 2026-08-27* below · Trust `marquee()` · Pain `stagger` · **Comparison** `fade-up` ×2 plus `buildComparisonScatter()` (the WITHOUT documents fly apart from the canvas centre, then every record ID on screen scrambles into its real value) · **Flow** `stagger` on node entrance, rail-lighting now scroll-scrubbed via `buildFlowScroll()` (was a timer-chain bloom loop) · Tour `scale-in` · Platform `stagger` · **Industry `fade-up` + `stagger` on the tab panels** · **Architecture** `draw` + `parallax` plus `buildArchitecturePulses()` (ambient core→node dots) · Testimonials `fade-up` · Closing `scale-in`.

**Motion, 2026-08-27 — signature-moment pass.** Added `SplitText`/`ScrambleTextPlugin` (already in `node_modules/gsap`, registered alongside `ScrollTrigger`/`Flip` in `animations.ts`) and a new `data-anim="split-lines"` case: text stays fully visible/paintable (no CSS pre-hide, unlike every other `data-anim` kind) until `document.fonts.ready` resolves, at which point `SplitText`'s `mask:"lines"` clips and reveals it — kept off the LCP-penalising `opacity:0` pre-state the rest of the system uses, deliberately, for the H1. `buildFlowScroll()` replaces `initFlowBloom()` outright (deleted, not deprecated) — same `.is-lit`/`.flow-seg-fill`/`.flow-seg-glow`/`.flow-seg-head` DOM and CSS, but driven by `ScrollTrigger` scrub instead of a `setTimeout` chain, so the record only travels as far as the reader has actually scrolled; it sets `transform`/`opacity` inline per frame (which always wins over the class-based CSS rules those elements still carry) and branches on `flow.css`'s own `max-width:767px` breakpoint since the rail's fill axis flips from X to Y there. `buildComparisonScatter()` and `buildArchitecturePulses()` are additive layers on top of the existing `fade-up`/`draw`/`parallax` reveals in those two sections, not replacements — lower regression risk than rebuilding either section's entrance from scratch. None of the three new functions touch markup; `buildArchitecturePulses()` in particular reads its six spoke endpoints straight off the existing `line[data-anim="draw"]` elements' own `x2`/`y2` rather than needing hand-authored coordinates.

**Trust is not just `marquee()`.** The legacy section also clones logos *to fill the width* (only the 8 in markup are originals — never hand-duplicate the row), magnifies whichever logo is nearest centre by writing a `--t` proximity value that `.trust-logo::after` reads for its halo, and names that logo live in `.trust-caption`. None of that is in `animations.ts` yet. The section is also height-budgeted to ~518px, with the arithmetic in a comment above `.trust` — read it before adding anything, and redo it if you do.

## Traps

- **Fonts shift layout on swap** — self-host with `size-adjust` before comparing anything visually. See step 1; they are not in the repo yet.
- **Hover is gated** behind `@media (hover: hover) and (pointer: fine)`. A tablet at 1024px is not a desktop.
- **`.hero-visual` is hidden below 1023px**; hero needs `min-height: 0` there (`index.html:2189-2193`). Hero height comes from `.hero-visual`, not `.hero` padding.
- **`.flow` SVG fans use `preserveAspectRatio="none"`** (`inventory.html:657`) — only straight lines survive. A circle becomes an ellipse; use a CSS `::after`. The fan endpoint percentages are computed row centres — recompute them if the row count, `gap` or row height changes.
- **Card photos are mixed aspect ratios.** Always `object-fit: cover` in a fixed frame; never `aspect-ratio` on the `<img>`.
- **Above ~1800px** percentage-width elements collide with the capped container. Use absolute offsets.
- **Bleeding elements** must be siblings of `.container`, not children — the nearest positioned ancestor wins.

More in **`legacy/CLAUDE.md` § Mistake log** (~40 entries, newest first). Read before touching the flow diagram, trust marquee, or platform tiles.

## Mistake log

Add an entry when something goes wrong or turns out to be a dead end. Newest first. Standing instruction — don't wait to be asked.

### 2026-08-27 — Comparison's WITH card overflowed the viewport at phone widths because a bare `1fr` grid track's auto-minimum was sized to the *other* (WITHOUT) panel, and the first stepper fix landed on another exact-fit edge case

- **Context:** User's screenshot (a ~390px phone) showed the dark "With NexOne" card badly broken: the `SO-9021` pill wrapped its own text onto two lines, "Customer name" did too, and the stepper's labels ran together as "DispatchedDelivered" with no space. Reproduced live against the dev server with Playwright at 320/375/390/430px rather than reasoning from the CSS alone, per this file's own repeated lesson.
- **Root cause, the real one — not in the card's own CSS at all.** `.cmp-panels { grid-template-columns: 1fr }` at the ≤1023px stacked breakpoint (`responsive.css`). A bare `1fr` track is shorthand for `minmax(auto, 1fr)`, and grid's automatic minimum is the *largest min-content width of every item sharing that track* — at the single-column breakpoint, both panels (WITHOUT collage and WITH card) share the one column. Measured directly (forced `.cmp-dark { width: 250px }` and found every child fit at 202px content width with zero overflow — so the card's own content was never the constraint): the WITHOUT collage's min-content width was pulling the shared track, and therefore the WITH card, out to 351px inside a 320px viewport. The header pills' text wrapping and the stepper collision were downstream symptoms of the card being squeezed back into the true 272px viewport width while still being laid out as if it had 351px — not upstream causes. **Fix:** `grid-template-columns: minmax(0, 1fr)` on both the desktop 2-column rule (`comparison.css`) and the stacked 1-column override (`responsive.css`), which removes the auto-minimum entirely.
- **A first, plausible-looking fix landed on its own exact-fit edge case and had to be redone.** Before finding the grid-track bug, tightened `.cmp-stepper`'s padding/font (`0 6px` / `10px`) to stop the labels overlapping. Verified clean at 390px — but at 320px the four labels' min-content widths summed to *exactly* the available inner width, leaving zero space for `justify-content: space-between` to distribute, so the words still touched with no gap ("DispatchedDelivered" again), just at a different breakpoint than before. **Fix:** padding to `0`, font to `9px`, and an explicit `gap: 6px` — gap is a floor `space-between` adds to, not a target it can be squeezed to zero, so it can't land on a zero-slack coincidence the way padding/font tuning alone can. **Do instead:** when sizing nowrap flex/grid items against a hard pixel budget, don't stop at "no overlap at the reported width" — check the narrowest supported width too (rule 9's 320px floor), and prefer an explicit `gap` over shaving padding/font until the numbers happen to clear, since the latter can re-produce the identical zero-slack failure one level down.
